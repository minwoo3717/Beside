# 사후 보고서 틀 (장애·훈련 공통)

장애가 나거나 '터뜨려 보기' 훈련을 하면 이 틀을 복사해 `docs/ops/postmortems/YYYY-MM-DD_<짧은 이름>.md` 로 남긴다.

- **왜 쓰는가**: 2026-11-25 멘토링에서 '한 번 터뜨려 보고 대응을 경험하라', '모니터링을 해야 감지가 빠르고 원인을 빨리 찾는다' 는 답을 받았다. 감지·진단·완화에 걸린 시간을 재야 그 말이 맞는지 보이고, 다음에 무엇을 고칠지 정해진다.
- **누구를 탓하지 않는다**: 무엇이 일어났고 무엇이 도왔는지만 쓴다.
- **표기**: 루트 CLAUDE.md 와 같다. [실험 결과] 는 데이터 폴더가 있을 때만 쓴다.
- **시각**: 모두 UTC 다.

### 1. 왜 (가설과 사용자 영향)

- 무엇을 확인하려 했나. 훈련이면 가설을 쓴다. 예: "Caddy 2g 상한에서 A1 9,000명이면 Caddy 가 OOM 으로 다시 시작된다".
- 가설이 맞으면 사용자는 무엇을 겪나. 예: 모든 연결이 2초 끊김, 업로드 실패, 600 s 대기.

### 2. 주입과 부하

- **주입**: 정확한 명령과 되돌리는 방법. 예: `scripts/fault/vm_drill.sh ...` 와 자동 되돌림 타이머.
- **부하**: 스크립트·환경 변수·단계. 훈련이면 `ABORT_ON_ERRORS=0` 을 적는다.

### 4. 감지

- **TTD**: 첫 알림 시각 − T0. 목표가 있으면 함께 적는다.
- **울렸어야 했는데 울리지 않은 알림**과 그 이유.
- 사람이 먼저 알았나, 알림이 먼저였나.

### 5. 영향

- k6: 상태 0 / 4xx / 5xx 수(코드별), 시간 초과 흐름.
- 작업: `INTERNAL_ERROR`·실패·잃은 작업 수, 가장 긴 대기.
- 외부 탐침이 끊긴 초.
